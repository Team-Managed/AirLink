Define the security architecture, threat model, OWASP Top 10 for LLM mitigations, input sanitization, zero-retention relay invariants, and hardware-backed credential storage following the `security-and-hardening` standard.

## Implementation

1. Enforce OWASP Top 10 for LLMs (2025) Defense-in-Depth:
   - **LLM01 (Prompt Injection Defense):** Never trust LLM output directly as raw shell execution or unescaped HTML. All tool calls generated by 0x Alpha or TrueForge must pass strict Zod schema validation before triggering local execution.
   - **LLM02 / LLM07 (Sensitive Information Disclosure):** API keys, session tokens, and file system secrets must be redacted before prompt assembly and filtered from outgoing WebSocket streams.
   - **LLM06 (Mitigating Excessive Agency):** Enforce the **Human-in-the-Loop (HITL) Invariant**: All destructive tool actions (`execute_bash`, `write_file`, `git_push`) are trapped in an unfulfilled Promise until explicitly approved via the mobile bottom sheet or PC terminal.
   - **LLM10 (Unbounded Resource Consumption):** Enforce strict execution caps:
     - 180-second timeout on all approval requests (auto-denied on expiration).
     - 500-event capacity limit on in-memory ring buffers.
     - 2 MB cap on per-command terminal output streaming.
2. Hardening Cloud Relay Server (`apps/relay/src/security.ts`):
   - **Stateless Zero-Retention Invariant:** The relay server must never persist prompts, diffs, tokens, or session history to disk or databases.
   - **Anti-Brute-Force Rate Limiting:** Track failed PIN pairing attempts per client IP. After 3 consecutive incorrect PINs, lock out the IP address for 5 minutes (`429 Too Many Requests`).
   - **Ephemeral Room TTL:** Automatically purge pairing rooms after 5 minutes of inactivity.
   - **Outbound-Only Tunneling:** The developer PC workstation maintains an outbound WebSocket client connection to the relay; no inbound listening ports are ever opened to the public internet.
3. In-Device Vault & API Key Protection (`apps/mobile/src/services/vault.ts`):
   - Store user-provided API keys (OpenRouter, DeepSeek, Anthropic) exclusively inside hardware-backed secure storage via `expo-secure-store` (iOS Keychain / Android Keystore).
   - Never transmit API keys to the relay server for storage; keys are injected in-memory strictly for active turn execution.
4. Input Validation & Secret Redaction (`packages/bridge-core/src/security/redactor.ts`):
   - Implement regex-based automated masking for sensitive patterns (`sk-[a-zA-Z0-9]{32,}`, `Bearer [a-zA-Z0-9._-]+`, `ghp_[a-zA-Z0-9]{36}`) replacing matches with `[REDACTED]`.
   - Sanitize all terminal logs and error payloads before transmission over WebSockets or writing to stdout.
5. Supply Chain & CI Security Gates:
   - Enforce frozen lockfile installs (`pnpm install --frozen-lockfile`) in CI.
   - Run automated Gitleaks secret detection (`.github/workflows/secret_scan.yml`) on all pushes to `main` and `dev`.
   - Execute automated dependency vulnerability audits (`pnpm audit --audit-level=high`).

## Scope Limits

- Do not store plaintext user API keys on local disk or cloud relays.
- Do not allow unauthenticated WebSocket connections to execute commands on the PC workstation.
- Do not execute destructive tool calls without human approval, regardless of LLM confidence scores.
- Do not bypass rate limiting or suppression checks.

## Notes

- Outbound-only tunneling completely eliminates the need for port-forwarding, ngrok tunnels, or dynamic DNS.
- Ephemeral PIN rooms ensure that compromise of the relay server yields zero persistent user code or credentials.
- Depends on: 00, 01, 03, 04, 10, 19. Required before: 16.

## Check When Done

- 3 failed PIN attempts from the same IP result in immediate 429 lockout.
- Destructive tool calls pause execution and auto-deny after 180s without human response.
- API keys and tokens are automatically masked into `[REDACTED]` in logs and stream events.
- Gitleaks and security audit pass cleanly in CI.
