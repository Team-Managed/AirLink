## Application Building Context

Read the following files in order before implementing or making any architectural decision:

1. `context/project-overview.md` — product definition, goals, features, hackathon tracks, and scope
2. `context/architecture-context.md` — system structure, deployables, boundaries, storage model, and invariants
3. `context/ui-context.md` — theme tokens, dark developer palette (#090d16), components, and motion conventions
4. `context/code-standards.md` — implementation rules, Zod protocol contracts, 5-layer prompts, and TDD
5. `context/ai-workflow-rules.md` — development workflow, scoping rules, Git conventions, and PR slicing
6. `context/progress-tracker.md` — current phase, completed units, open questions, and next steps

Update `context/progress-tracker.md` after each meaningful implementation change.

If implementation changes the architecture, scope, or standards documented in the context files, update the relevant file before continuing.
